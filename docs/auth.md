# 注册、登录与会话设计

状态：设计方案，尚未实现。

## 范围

- 账号注册、登录、退出，以及查询当前登录用户。
- `/` 是公开的活动宣传海报首页，不要求登录；登录与注册使用独立的 `/login` 页面。
- 管理页面及管理接口需要登录；现有公开活动页面、公开活动列表和访客报名保持匿名可用。
- 现有 `POST /api/public/activities/{activity_id}/register` 是活动报名，不是账号注册；新增账号接口使用 `/api/auth/register`，避免混淆。
- 账号是否有管理权限必须由服务端判定，前端只据此调整显示。

## 会话标识

采用服务端会话：登录成功后使用安全随机数生成不透明的会话令牌，浏览器只保存 Cookie，不在 `localStorage` 存储令牌或“已登录”标记。

- Cookie 名称建议 `balancer_session`；设置 `HttpOnly`、`SameSite=Lax`、`Path=/`，在 HTTPS 环境设置 `Secure`。部署时应使用 HTTPS；不要把仅用于开发的非 `Secure` Cookie 带到生产环境。
- Redis 保存 `session:<令牌摘要> -> user_id`，通过 TTL 自动过期。建议初始有效期为 7 天，并使 Cookie 的 `Max-Age` 与 Redis TTL 一致；采用固定过期时间，避免每个请求续期。
- Redis 只保存令牌的 SHA-256 摘要，不保存明文令牌；Cookie 只保存明文令牌。生成令牌时使用密码学安全随机源（如 `secrets.token_urlsafe(32)`）。
- 每次受保护请求从 Cookie 读取令牌，查询 Redis 并确认用户仍然存在且有权限；无效或过期返回 `401`，权限不足返回 `403`。不因前端显示了管理界面就信任该请求。
- 登录时签发新令牌；退出时删除 Redis 中的会话并清除 Cookie。修改密码或禁用账号时应使该账号已有会话失效。Redis 数据丢失时用户需重新登录，不应回退到匿名管理权限。
- 对使用 Cookie 的写接口，除了 `SameSite` 还应校验请求 `Origin`（或使用 CSRF 令牌）；登录和注册接口也应纳入该校验。反向代理部署时只信任明确配置的外部来源，不从任意请求头推断可信来源。

## 数据与接口

MongoDB 新建 `users` 集合：`_id`、唯一且规范化的账号名、`password_hash`、`role`、`created_at`、`disabled`。密码使用 Argon2id 哈希，不保存明文，也不在响应中返回哈希。注册时对规范化账号名建唯一索引；重复账号返回 `409`。登录失败统一返回不透露账号是否存在的提示，并对登录与注册尝试限流。

| 接口 | 作用 | 访问规则 |
| --- | --- | --- |
| `POST /api/auth/register` | 创建普通用户账号 | 匿名可访问；管理员账号不从此接口创建 |
| `POST /api/auth/login` | 校验凭据并写入会话 Cookie | 匿名可访问 |
| `GET /api/auth/me` | 返回当前用户的 ID、账号名和角色 | 未登录返回 `401` |
| `POST /api/auth/logout` | 删除当前会话并清除 Cookie | 已登录 |

前端同源调用 `/api`，默认会携带同源 Cookie，无需手动传递会话令牌。页面加载时调用 `/api/auth/me` 获取真实状态；收到 `401` 时显示登录界面，登录或退出后重新获取状态。

页面职责如下：

- `/`：公开宣传首页，展示社团与活动，不放登录弹窗，也不因登录状态改变访问要求。
- `/login`：独立登录和普通账号注册页面。普通账号可以注册，但不能获得管理权限。
- `/admin`：管理后台页面。页面脚本先调用 `/api/auth/me`，未登录或非管理员跳转到 `/login`；真正的数据保护仍由后端接口完成。

## 权限边界

- `/api/public/activities` 和 `/api/public/activities/{activity_id}/register` 保持公开；首页 `/` 和公开页面资源也保持公开。
- `/admin` 页面入口、`/api/activities`、`/api/categories` 及 `/api/uploads/image` 等管理接口必须在后端检查管理员权限，包括读取、修改和上传。静态文件 `/static` 可公开提供，但不能作为授权边界；管理数据只能通过受保护接口获取。
- `/uploads` 当前公开提供文件；登录保护管理接口不会自动使已上传图片私有。如将来需要私有图片，须另行调整文件访问方式。
- 普通用户注册后不能自动获得管理员权限。首个管理员如何创建（部署脚本或人工初始化）须在实施前确定；不能通过公开注册接口自选 `role`。

1. 引入 Redis 客户端与 Argon2 密码哈希依赖，建立用户唯一索引，提供管理员初始化方式。
2. 实现注册、登录、当前用户、退出接口及会话校验依赖；配置可信来源与 Cookie 的 HTTPS 行为。
3. 为管理页面与所有管理 API 加权限检查，再接入前端登录界面及状态处理。
4. 验证匿名仍可浏览和报名活动；匿名访问管理接口返回 `401`，普通账号返回 `403`，管理员可访问；验证重复注册、错误密码、退出、过期、禁用账号、跨站写请求，以及 HTTPS 下 Cookie 属性。
